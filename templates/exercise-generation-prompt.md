# Contexto

Este tema pertenece a mi roadmap de fundamentos de ingeniería de software.

La práctica debe ayudarme a comprender el concepto, no simplemente a escribir código por escribir.

Antes de generar ejercicios, analiza qué tipo de práctica es adecuada.

Puede ser:

- código
- experimento
- análisis
- debugging
- diseño
- comparación
- interpretación de resultados
- explicación conceptual

Si el tema es principalmente teórico y no tiene sentido programar, NO fuerces ejercicios de código.

# Objetivo

Genera una colección pequeña de ejercicios que permita pasar de comprensión básica a aplicación.

Quiero ejercitar:

- razonamiento
- comprensión
- implementación cuando aplique
- detección de errores
- criterio técnico

## 2. Ejercicio básico

Incluye:

- objetivo
- contexto
- enunciado
- restricciones
- qué debería aprender

## 3. Ejercicio intermedio

Debe requerir combinar varios conceptos del tema.

Incluye:

- objetivo
- enunciado
- restricciones
- qué debería analizar
- errores comunes que debo intentar evitar
- criterios de validación

No incluyas la solución.

---

## 4. Ejercicio avanzado

Debe requerir mayor razonamiento.

No significa necesariamente más código.

Puede implicar:

- detectar un problema
- comparar alternativas
- optimizar
- depurar
- diseñar
- explicar comportamiento inesperado

Incluye criterios de validación.

---

## 5. Ejercicio de code review o análisis

Si aplica, muestra:

- un pequeño fragmento de código
- una solución conceptual
- un diagrama
- una configuración

y pídeme identificar:

- errores
- riesgos
- mejoras
- comportamiento esperado

No reveles inmediatamente las respuestas.

---

## 6. Ejemplo resuelto de referencia

Incluye un ejercicio diferente a los anteriores y resuélvelo completamente.

Quiero ver:

1. cómo analizar el problema

3. cómo elegir una solución
4. implementación si aplica
5. cómo comprobar el resultado
6. qué errores podrían cometerse

La solución debe servir como guía de razonamiento, no únicamente como código final.

# Reglas

- Entre 3 y 5 ejercicios es suficiente.
- Prioriza calidad sobre cantidad.
- No crees aplicaciones grandes.
- Los ejercicios deben poder vivir dentro de `labs/`.
- Usa Python cuando el ejercicio requiera código, salvo que el tema sugiera otro lenguaje.
- No incluyas la solución de los ejercicios propuestos.
- Solo el ejercicio de referencia debe estar resuelto.
- Si un tema no requiere código, reemplaza la implementación por análisis, diagramas o razonamiento.
